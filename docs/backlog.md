# 第二版及以后

讨论中明确推迟、后续要实现的功能。术语含义见 `CONTEXT.md`。

| 功能 | 说明 | 推迟原因 |
| --- | --- | --- |
| 自定义 Action | 用户新增 Action：名称 + 图标 + 提示词，可排序、启停；同时开放修改内置 Action 的提示词 | 第一版先固定 4 个默认 Action，提示词写死 |
| 更多内置 Action | 总结、润色等，默认不在 Action Bar 上 | 同上 |
| 驻留期间划词引用到追问 | 驻留状态下在别处划词，自动把选区引用进追问输入框，而不是被忽略 | 与单窗口浮层的状态管理冲突，复杂度高 |
| 替换原文 | 把 AI 结果写回宿主应用，替换选中的文字 | 需要模拟粘贴，跨应用可靠性差 |
| 对话历史 | 保存追问对话，可回看 | 第一版对话随面板关闭结束 |
| 更多 Provider 接口 | Anthropic 原生、Gemini 原生（pi-ai 都已支持，接入即可） | 第一版只引入 OpenAI 兼容和 Responses 两个实现，控制体积 |
| ChatGPT 订阅登录 | 用 Sign in with ChatGPT 登录，消耗用户的 Plus / Pro 额度，不填 Key；设计见 ADR 0003 | 第一版先只支持 API Key；登录流程要用 Rust 另写 |
| 选区所在章节标题 | 在辅助功能树里从选区往上找最近的标题，作为环境的一部分发给模型 | 各应用的辅助功能树结构差异大，要先原型验证 |
| 浏览器扩展 | 通过 Native Messaging 把网页正文、`<meta>` 描述、选区所在章节交给点拨，上下文更完整；见 ADR 0004 | 要为每个浏览器单独发布扩展，用户要多装一样东西 |
| 截图作为上下文 | 截取选区附近的屏幕交给视觉模型，适用于读不到文字结构的应用 | 需要屏幕录制权限，隐私风险大，请求更慢更贵 |
| 按 Action 选模型 | 每个 Prompt Action 可以单独指定模型，例如翻译用便宜快速的模型、解释用更强的模型 | 第一版只设一个全局默认模型 |
| 按应用设置放置方向 | 在自带划词工具栏的应用（Notion、飞书文档等）里改变浮层位置 | 有浮标后遮挡问题已大幅缓解 |
| 系统毛玻璃 | 浮层使用 macOS vibrancy / Windows Acrylic；方案：形变时用实色，动画结束后淡入毛玻璃 | 系统毛玻璃铺满整个窗口，与"大透明窗口 + 网页内形变"冲突 |
| 正式签名与公证 | macOS 用 Apple Developer ID 签名 + 公证（每年 99 美元）；Windows 代码签名证书，避免 SmartScreen 警告 | 自用阶段用本地自签名证书即可 |
| Linux 支持 | X11 完整支持；Wayland 降级为快捷键唤出、屏幕居中 | Wayland 不允许全局鼠标监听和自由定位窗口 |
