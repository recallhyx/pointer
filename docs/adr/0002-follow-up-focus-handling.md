# 0002 追问时浮层如何获得键盘焦点

状态：已接受

## 背景

浮层原本全程不抢焦点，这样宿主应用的选区和输入状态不受影响。支持追问后，结果面板必须能接收键盘输入，两个平台的系统行为不同。

## 决策

- 追问前：浮层保持不抢焦点（与 ADR 0001 一致）。
- 用户点进追问输入框时才申请键盘焦点：
  - **macOS**：浮层本来就是非激活浮层（NSPanel），允许它成为接收键盘输入的窗口，但不激活整个应用。宿主应用仍是"当前应用"，菜单栏不变。Spotlight、Raycast 也是这种做法。
  - **Windows**：不激活的窗口收不到键盘输入，只能把浮层切到前台，宿主应用会暂时失去前台。打开浮层时记录宿主应用的窗口句柄，浮层消失时把前台还给它。
- 用户已经开始追问，就不再允许"点外面消失"，避免误点丢失对话。

## 后果

- Windows 上用户点进输入框的那一刻，宿主应用的窗口会变成非活动状态（标题栏变灰、选区高亮变淡）。取词在这之前已经完成，不影响功能。
- 把前台还给宿主应用依赖 Windows 的前台切换规则：浮层自己在前台时有权限切换，但宿主窗口已被关闭等边界情况要兜底。
- 驻留期间新的划词不会触发浮层，用户要先关掉当前对话。
