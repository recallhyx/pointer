# 0001 用 Tauri 2，浮层的所有状态共用一个窗口

状态：已接受

## 背景

- 需要同时支持 macOS 和 Windows，并且要求轻量、交互动画非常流畅。
- 浮层要从浮标形变成 Action Bar，再形变成结果面板，不能有新开窗口的白屏或闪烁。
- 结果面板要流式渲染 Markdown（代码块、表格、公式）。
- 技术栈不受开发者熟悉程度限制。

## 决策

- 用 **Tauri 2**：Rust 负责取词、全局鼠标监听、窗口管理，以及模型请求的实际发送、代理和 Key 保管；React + TypeScript 负责浮层和设置界面，并用 pi-ai 组装模型请求、解析流式结果（见 ADR 0003）。
- 浮层是**一个启动时就预先建好、平时隐藏的窗口**，三种状态之间的形变都在网页内部完成，动画用 Motion 的 layout 动画实现（CSS View Transitions 作为备选）。
- 窗口每次划词只设一次：大小能装下气泡、Action Bar 和最高的结果面板，再加阴影和回弹余量；之后形变只在网页里做，不再改窗口。透明区域按鼠标位置切换点击穿透（见下方「修订」）。
- 不抢焦点：macOS 上把窗口转成非激活浮层（NSPanel，可用 `tauri-nspanel` 或 objc2 自己写）；Windows 上设置不激活的窗口样式。

## 考虑过的方案

- **两边各写一套原生界面（Swift + C#），或用 Rust 共享核心 + 原生界面**：手感上限最高，透明区域点击穿透是系统自带能力。放弃原因：界面和动画要写两遍、两边视觉难以保持一致；Windows 原生框架里流式渲染 Markdown 的方案很弱；而能共享的逻辑（调用模型、配置）本来就很薄。
- **Electron**：Cherry Studio 和 AIA 都用它，生态成熟。放弃原因：体积和内存与"轻量"目标冲突；而且浮层行为照样需要原生代码兜底（Cherry 自带了 `selection-panel.node`）。

## 后果

- Mac 版需要开启 Tauri 的私有接口开关（`macOSPrivateApi`），因此不能上架 Mac App Store，只能官网分发。
- 浮层贴近屏幕底部、需要向上展开时，窗口左上角会移动，网页内容必须在同一帧里反向偏移，否则会抖一下；这一点需要最先做原型验证。
- 动效带回弹，外形会短暂超出最终尺寸，所以窗口撑大时要按目标尺寸再多留一圈回弹余量（约 5–8%），否则回弹的那一下会被窗口边缘裁掉。
- 形变开始前必须先知道新内容的尺寸，才能提前撑大窗口：新内容先在不可见状态下渲染并测量，再同时启动窗口调整和形变动画。结果面板的最终高度要等流式输出结束才知道，所以形变的目标是面板的初始尺寸，之后随内容增长逐步变高。
- 收起时没有回弹，窗口可以在动画结束后再缩小，不需要额外余量。
- 如果原型证明某个平台的手感不达标，只替换该平台的浮层窗口实现，Rust 里的取词和模型调用部分保留。

## 修订（2026-10）：去掉「随形变调整」窗口

原决策是窗口跟着内容走：每次形变前把窗口撑大，结束后缩回。原型里把它和「固定窗口」做成两个可切换的模式对比。真机（macOS）上随形变调整会明显闪烁、抖动：原生窗口移动和网页重绘不在同一帧，向上展开时尤其明显。因此删掉这个模式，只保留固定窗口，设置项和 `windowMode` 字段一并移除，旧 `settings.json` 里残留的 `windowMode` 会被忽略。上面「后果」里关于撑大窗口、反向偏移和收起后缩小的几条随之不再适用；回弹余量仍然保留在固定窗口的尺寸里。
